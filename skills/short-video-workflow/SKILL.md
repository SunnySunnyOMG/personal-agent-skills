# Short Video Workflow

用 Agent 从一句选题做到成片：查证、写稿、配音、用代码做画面、自己检查、出片。人只做三件事：给观点、挑方向、审片。

这份 Skill 只有流程和核对动作，**不含任何人的风格和经验**。你的规矩写在你自己的规矩文件里（模板见 [rules-file.template.md](references/rules-file.template.md)），每做完一期往里加，下一期开工先读它。

## 边界

- 本 Skill 不发布、不上传、不登录任何平台。对外发布由主人自己做。
- 工具都可替换。下文提到的工具只是例子，按主人已有的工具和权限来。
- 不编造素材：要展示的结果、截图、数字必须有来源，或当场做实验得到。查不到就改说法，或告诉主人。

## 0. 开工

1. 读主人的规矩文件。没有的话，用模板新建一份，先空着。
2. 确认这期的规格：画幅、帧率、时长上限、配音音色、字幕样式。规矩文件里已有的直接用，不再问。
3. 确认素材和隐私边界：画面里不能出现什么（账号、路径、密钥、他人姓名、内部项目……）。

## 1. 选题与查证

- 把主人的一句话写成企划第一行：「这期讲的是 ____，所以你可以 ____」。写不成一句，说明是两期。
- 每个说法找到出处。关键句打开原始页面取原文，不用二手摘要。资料多时可以分几个子任务并行查。
- 查不到的说法：做一个小实验并把记录存进工程，或者改成「我们的看法」，或者删掉。
- 给主人两三个方向（故事线、开头），由主人挑。

**核对：** 企划里每个事实都标了来源或实验记录。

## 2. 写稿

1. 先写骨架：五六行，每行是观众此刻的一个问题，下一行回答它。骨架念不通就不写口播。
2. 再写口播。段落之间能用「所以」「但是」连起来；只能用「然后」「另外」连的段落，挪走或删掉。
3. 做节拍表：逐句标成钩子、回报或铺垫，写上预计时间。每个钩子都要找得到对应的回报。连续铺垫的长度上限写进规矩文件。
4. 三个自查：只读各段首句，连起来要念得通；逐段做删段测试；不看稿用三句话复述。

**核对：** 骨架、口播、节拍表存在同一份脚本里。

## 3. 配音

- 送去合成前，按规矩文件改写容易读错的字（多音字、数字、年份、英文名等）。字幕仍按原稿。
- 合成后，把音频转写回文字和稿子逐字对，听错的地方回到上一步改写再合成。
- 配音文件就是全片的时钟。改了口播，就重新合成、重新对时间。

**核对：** 有一份转写记录，写明哪些差异只是同音字、哪些是真读错。

## 4. 画面

- 画面用代码生成（例如用 HTML 和动画库逐帧渲染成视频），不手工剪。画面能反复改，每次渲染结果一样。
- 关键词、数字、印章这类元素，按配音里说到它的那一刻出现。时间从配音的转写里取，不靠手调。
- 一个生成脚本读口播和配音时间，写出整条片子；改稿后重跑脚本即可。
- 讲同一个要点时，画面上那件东西不换，只改它身上的一处。

**核对：** 生成脚本、口播、配音时间三者一致，没有手改的生成产物。

## 5. 检查

- 跑一遍自动检查：文字重叠、溢出、字号太小、对比度不够。错误清零，警告逐条看过。
- 在每个改动处截帧，自己看一遍：字幕有没有挡住内容，断行有没有把词拆开，标注有没有盖住要读的字。
- 逐项过主人的隐私清单。

**核对：** 有截帧，并记下看到的问题和处理办法。

## 6. 出片

- 渲染，调响度（目标值写进规矩文件），压缩。
- 从成片抽帧再看一遍，把成片的声音转写回来，和稿子再核一次。
- 交付时报告：时长、响度、检查结果、转写核对结果、哪些没验证（例如没在手机上看过），以及需要主人决定的事。

## 7. 收尾：更新规矩文件

主人审片后，把这期能复用的做法和踩过的坑写进规矩文件，注明来自哪一期、为什么。只出现过一次、说不清会不会再遇到的事，先简记，不升级成规矩。下一期从第 0 步开始，先读它。
